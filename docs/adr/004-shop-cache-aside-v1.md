# ADR 004：商户 Cache Aside 与有界后台重建

## Context

基础业务阶段先实现 GET → SELECT → SET、固定 30 分钟 TTL 的 Cache Aside V1。基础链路完成后，真实 MySQL/Redis 对照显示：100 次重复空查询读取数据库 100 次；同一冷 ID 的 64 个重叠请求读取 64 次。暖缓存 100 次读取没有回源。并发样本人为增加 50ms 数据库延迟以制造重叠，不能解释为线上性能数字。

2026-09-17 基于该证据演进到当前 V2 缓存格式，保留本 ADR 文件路径及测试中的冻结 V1 参考。完整环境、命令与结果见 [缓存对照](../performance/cache.md)。

## Decision

- 分类与列表直接查询 MySQL，稳定排序并限制单页大小与查询深度。
- 正缓存逻辑刷新时间为 30 分钟加 0–5 分钟随机量，硬过期再晚 5 分钟；逻辑过期先返回旧值并刷新，硬过期后停止返回旧值。
- 仅将真实不存在结果缓存 30–45 秒，不把数据库故障写成空值。
- 用本地有界 singleflight 按 ID 合并冷查询和后台刷新，最多 64 个不同 ID；容量耗尽时新冷查询返回 429，已有旧值仍可读。
- 任务属于服务生命周期，请求取消不取消共享任务。重建预算 2 秒，缓存单次 I/O 100ms；失败退避另有最多 100ms 写入预算，将下次刷新延后最多 5 秒，不延长硬过期。关闭时先排空 HTTP，再取消并等待任务，最后关闭依赖。
- Redis key 为 `locallife:shop:v2:<id>`，原始缓存内容作为 Lua CAS token。重建任务再次读取 Redis 后查询 MySQL，仅在 token 仍相同时发布，避免覆盖已经变化的缓存记录。
- `shop-update` 仅维护名称与地址，先提交数据库再 DEL；删除失败保留已提交结果，命令报错提示重试。不新增商户管理 HTTP 接口。

## Alternatives

1. 维持 V1 或只查询数据库：实现简单，但无法抑制已测得的重复回源。
2. 只用互斥锁同步重建：可合并回源，但热点逻辑过期时所有请求都等待数据库。
3. 分布式锁、永久版本键、延迟双删或 CDC：能覆盖更多跨进程和写入竞争，增加租约、版本保留、重试或额外组件的恢复成本。
4. 多级本地缓存：可减少 Redis 调用，但进一步增加跨实例失效与内存管理成本，当前没有对应基线依据。

## Why not alternatives

名称和地址允许短期旧值，当前负载证据集中于同进程重复回源，因此采用单进程合并和有界旧值。Redis 故障时仍尝试读取 MySQL，使用任务容量与超时限制单进程的在途工作。TTL 抖动分散到期时间，但不能阻止 Redis 整体故障造成的回源压力。

## Consequences

- 对照中重复空查询、重叠冷查询均降为一次数据库读取，暖缓存继续零回源。它证明指定场景的负载放大下降，不证明整体 QPS 提升。
- 逻辑过期允许旧值；新建的同 ID 商户可能受空值缓存影响最多约 45 秒。JSON 元数据、空值 key 和额外 Redis 读取也增加内存与请求成本。
- CAS 仅保护发布，token 来自重建任务的第二次 GET。非空 token 被删除或替换后拒绝旧发布，但冷请求仍可能加入旧在途任务并收到旧行。
- 第二次 GET 为空或失败时，空 key → 更新并 DEL → 空 key 的竞争无法检测，旧数据可能被回填至本次硬过期。当前不保证强一致，也不跨进程合并回源；完整边界见 [接口契约](../api/shop.md#缓存一致性边界)。
- Redis 故障会增加数据库压力，并使共享退避写入失效。64 是在途任务上限，不是数据库 QPS 限流器；随机 ID 持续请求仍需后续指标观察。启动与 readiness 仍检查 Redis，认证继续依赖其可用性。
- 数据库已提交、缓存 DEL 失败时没有自动补偿队列，维护者需在 Redis 恢复后重试。专用缓存指标尚未接入。
- offset 分页不提供并发增删时的快照保证；GEO 模块独立定义距离排序查询。

## When to revisit

多实例回源压力显著、业务要求更新后立即可见，或随机 ID 穿透导致数据库持续饱和时，先补负载与故障证据，再评估跨进程协调、版本化失效和请求级限流。

## Validation

单元测试覆盖空值、同 ID 合并、请求取消隔离、容量、普通错误与超时退避、硬过期和关闭。真实 MySQL/Redis 测试覆盖 Lua CAS、失效竞争、旧值刷新、删除转空值、随机 TTL、名称地址更新及数据库回源对照。实际 HTTP 与维护命令验证数据库提交后删除缓存、返回旧值后后台刷新、404 空值 TTL。执行方法见 [测试说明](../testing.md)。
