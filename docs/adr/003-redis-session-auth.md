# ADR 003：验证码登录与 Redis Session

状态：Accepted，User 模块。

## Context

认证需要首次登录创建用户、请求间携带身份、过期和主动退出。多个并发请求可能使用同一个验证码或同时首次注册，必须由存储层保障一次性与唯一性。

## Decision

- 使用手机号验证码和随机 Token。Token 由 32 字节密码学随机数生成，编码为 43 字符 Base64URL。
- Redis Session 只保存用户 ID，key 使用 Token 的 SHA-256；固定 TTL 默认 30 分钟，读取不续期。用户信息从 MySQL 查询。
- 验证码保存摘要和剩余尝试次数，默认 5 分钟有效、60 秒重发冷却和 5 次错误尝试。短 Lua 脚本原子处理发布/冷却及校验/消费；同手机号 key 使用相同 hash tag。
- MySQL 手机号唯一索引裁决首次注册并发；插入冲突不覆盖已有资料，再读取权威用户记录。
- 鉴权中间件读取 Bearer Header，将用户 ID 放入 typed context。Handler 只解析请求、调用 Service 并映射响应。
- 尚未接入短信供应商。开发验证码只在显式配置开启且监听回环地址时返回，默认关闭；关闭时验证码接口返回 503。

## Alternatives / Why not alternatives

- JWT：减少每次鉴权的 Redis 读取，但即时注销需要额外撤销或版本状态；当前已有 Redis，直接维护会话更简单。
- Redis GET 后再 DEL 验证码：存在并发复用窗口，使用短 Lua 脚本将验证、错误次数和消费合为原子操作。
- 查询用户后无约束地 INSERT：并发首次登录可能重复注册；用数据库唯一索引兜底。
- 滑动会话过期：交互更连续，但会延长被窃取 Token 的有效时间并增加写流量；当前采用固定 TTL。

## Consequences

Redis 故障时鉴权失败关闭，返回依赖错误；不降级到匿名用户或本地缓存身份。多个登录会话可共存，退出只撤销当前 Token。

验证码在访问 MySQL 前已经消费。后续失败时不恢复旧验证码，避免重放；客户端重新申请验证码。此流程不提供跨 MySQL/Redis 的分布式事务保证。

开发模式不是短信身份验证。接入真实短信前需要独立处理供应商失败、发送幂等及全局/IP 配额；当前没有向外发送短信。

## When to revisit

接入正式短信通道、引入账号封禁/所有设备注销，或会话规模导致 Redis 压力时，分别评估投递适配、会话索引与分区策略。不要同时叠加第二套认证协议。

## Validation

真实 Redis 验证并发单次消费、冷却、错误尝试耗尽、验证码过期、Session 固定过期和注销；真实 MySQL 验证并发注册只生成一个用户。HTTP 集成覆盖登录、重复登录、重放、当前用户、退出、过期和依赖故障。日志测试确保验证码、Token 和手机号不出现在访问日志中。
