# 附近商户与 GEO 索引

`GET /api/v1/shops/nearby`，无需登录，返回统一响应中的商户数组。

| 参数 | 默认值 | 约束 |
| --- | --- | --- |
| type_id | 必填 | uint64 正整数 |
| longitude | 必填 | -180 至 180，经度 |
| latitude | 必填 | -85.05112878 至 85.05112878，Redis GEO 支持的纬度范围 |
| radius_m | 5000 | 1–50000 米 |
| limit | 10 | 1–50 个候选 |

拒绝 NaN、Infinity、显式空值、重复的已知参数及越界值。当前是附近候选列表，不提供分页；未知参数被忽略。

```http
GET /api/v1/shops/nearby?type_id=1&longitude=121.4737012&latitude=31.2304001&radius_m=5000&limit=10
```

成功的 `data`：

```json
[
  {
    "id":"1",
    "type_id":"1",
    "name":"示例·街角面馆",
    "address":"上海市示例路 1 号（虚构商户）",
    "longitude":121.4737012,
    "latitude":31.2304001,
    "distance_m":0.12
  }
]
```

`distance_m` 是 Redis GEO 到查询坐标的近似球面距离，单位米；索引压缩坐标会带来误差，即使输入相同坐标也可能不完全为零。结果按距离递增，同距离项不承诺额外顺序。商户名称、地址等实体字段从 MySQL 批量读取，不使用详情缓存。

## 索引构建

先迁移、导入商户数据，再执行：

```powershell
go run ./cmd/geo-rebuild
# 也可仅重建指定分类：
go run ./cmd/geo-rebuild -type-id 1
```

默认遍历数据库中的全部当前分类；指定不存在的分类会失败。重建整体超时为 5 分钟，支持 Ctrl+C 取消。每个分类独立发布，日志记录完成的分类与条目数；后续分类失败时，之前已成功发布的分类保留新版本。

每类先从 MySQL 读取商户，再分批写入临时 Redis GEO key，临时 key 带 10 分钟 TTL。发布脚本核对实际条目数后，原子替换正式索引并更新 ready 标记；临时索引不完整或读取数据库失败时，保留旧索引。正式索引不设置 TTL。

查询在一个 Redis 事务内读取标记与位置索引，避免与发布过程交叉读到不同版本。空分类会发布明确的空索引；未初始化、marker 丢失、非空索引整体丢失或 Redis 出错时返回 503，不把未准备好误报为空列表。

## 数据一致性与当前边界

- MySQL 是商户实体来源；Redis 仅保存分类下的 ID 和位置。
- 当前没有商户写接口。导入商户、修改位置/分类或删除商户后需要重新运行索引重建命令；Redis 数据清空后也需重建。
- 对每个分类的数据库读取是单条 SELECT，跨分类不提供共同快照。重建期间应暂停导入/修改，且避免同时运行多个重建命令；并发重建以最后发布的版本为准。
- 本版本按分类将数据加载到内存，再按 500 条分批写 Redis，适合当前项目数据规模。没有实现变更订阅或增量索引同步。
- 先取最近的 `limit` 个索引候选，再去掉已删除或已改分类的数据库记录，所以索引过期时结果可能少于 limit；不会额外补满候选。
- 距离仍基于最后重建的索引坐标，位置修改后需要重建才能更新距离；数据库行仍是当前字段。
- Redis GEO 不支持极区纬度。若数据库中存在超出支持范围的位置，重建该分类失败，需修正数据或采用其他位置索引方案。

## 错误响应

| HTTP | code | 含义 |
| --- | --- | --- |
| 400 | validation | 参数缺失、无效或越界 |
| 408 | request_canceled | 请求取消 |
| 503 | dependency_failure | 索引未准备好、索引损坏或依赖故障 |
| 504 | timeout | 请求超时 |

没有已初始化索引的分类 ID，包括未导入的分类，返回 503。索引已初始化但范围内没有结果时返回 `[]`。
