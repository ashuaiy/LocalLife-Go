# LocalLife-Go

基于 **Go、CloudWeGo Hertz、GORM、MySQL 和 Redis** 的本地生活服务后端，采用模块化单体架构，围绕用户、商户、探店内容、关注动态和优惠券构建业务模块。

> 已完成基础框架与用户认证模块，其余业务功能正在逐步开发。

## 技术框架

| 技术 | 用途 |
| --- | --- |
| Go | 服务端开发语言 |
| CloudWeGo Hertz | HTTP 服务、路由和中间件 |
| GORM | 数据库访问 |
| MySQL | 业务数据持久化、事务与数据约束 |
| Redis | 验证码与会话存储；后续扩展缓存、地理位置索引与异步处理 |
| golang-migrate | 版本化 SQL 数据库迁移 |
| slog | 结构化访问日志 |
| Docker Compose | 本地开发与集成测试依赖编排 |

## 架构设计

采用模块化单体设计，业务模块按以下职责分层：

- **Handler**：请求解析、参数校验和响应映射。
- **Service**：业务规则、事务边界与缓存协调。
- **Repository**：数据持久化与查询。
- **Middleware**：请求标识、超时控制、异常恢复与访问日志。

MySQL 作为业务数据的权威来源，Redis 当前承载验证码与会话，后续用于缓存与辅助索引。请求通过 `context.Context` 传递上下文和超时，连接池由应用统一管理。

用户模块已按 Handler / Service / Repository 分层实现，其余业务模块沿用相同结构。

## 已实现功能

- **用户认证**：手机号验证码登录、首次登录创建用户、随机 Bearer Token 与 Redis Session、当前用户查询和退出登录。开发验证码需显式开启，短信通道尚未接入。
- **会话与验证码策略**：固定会话 TTL、验证码有效期与重发冷却、错误尝试上限、验证码原子消费、并发注册去重。
- **配置管理**：环境变量加载、类型解析与参数校验。
- **HTTP 服务**：Hertz 路由、统一 JSON 响应与错误分类。
- **请求处理**：Request ID、上下文超时、异常恢复和结构化访问日志。
- **依赖连接**：MySQL / Redis 连接池、启动连通性检查与资源释放。
- **健康检查**：`GET /healthz` 检查服务存活，`GET /readyz` 检查依赖可用性。
- **生命周期管理**：启动错误处理、信号响应与优雅退出。
- **数据库迁移**：用户、商户类型、商户、探店内容、关注关系、优惠券、秒杀库存和订单的初始表结构，包含订单唯一约束与库存非负约束。
- **测试支持**：配置、错误映射、HTTP、生命周期与认证测试；真实 MySQL / Redis 集成测试，以及容器化 Race 检查。

## 当前接口

| 方法 | 路径 | 功能 |
| --- | --- | --- |
| POST | `/api/v1/auth/code` | 获取开发验证码，受开关与重发冷却限制 |
| POST | `/api/v1/auth/login` | 验证码登录，创建用户或复用已有账号 |
| GET | `/api/v1/users/me` | 查询当前登录用户 |
| POST | `/api/v1/auth/logout` | 注销当前会话 |
| GET | `/healthz` | 服务存活检查 |
| GET | `/readyz` | MySQL / Redis 可用性检查 |

用户查询与退出登录通过 `Authorization: Bearer <token>` 鉴权。接口契约见 [用户认证接口](docs/api/auth.md)，模块职责见 [架构说明](docs/architecture.md)。
